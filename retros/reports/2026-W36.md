## What's working (preserve these)

- **Mapping the design/architecture question before writing code.** Deciding
  read-only-vs-editable up front (multi-part assembly view), choosing the
  integration architecture before any feature code (Blender-parity verbs),
  and reading the *tests* before touching the packer (3MF packing strategy)
  each collapsed what would have been multiple rework rounds into one
  confident pass. Keep leading with this.
- **The spec-driven Playwright screenshot as the highest-signal verification
  step.** Independently credited across UI work (assembly view, 3MF export
  dialogs) for catching wiring bugs — a pool that never resolved, edit tools
  acting on a hidden part — that typecheck/unit never could.
- **The inverse-CAD PLAYBOOK ratchet keeps compounding.** Across three
  consecutive phases (v2 framework, armor genericity, the foreign Benchy
  mesh) a recipe that matured on early parts transferred near-verbatim to
  later, harder ones — armor went 13-for-13 with "no new tactics needed,"
  and Benchy (a never-seen 225k-tri internet mesh) converged with zero
  part-specific babying. The mechanism (merge each returning agent's
  tactics into the shared PLAYBOOK before the next wave) is doing real
  work — the friction items below are about the *orchestration* around it,
  not the convergence method itself.
- **Per-part `expectComponents` / gate assertions catching real defects
  before they ship** (multi-part kits) — simplify-fusing articulated
  pieces, debris masquerading as parts, and a non-deterministic
  `decompose()` were all caught before anything was baked.
- **`work-reviewer` earning its keep on both entries that used it** — it
  caught a collapsed-groups drag regression and a JSON-manifest
  serialization diff the author's own e2e coverage missed.

## Top friction (ranked by cross-session frequency × cost)

1. **[inverse-cad] Multi-agent orchestration bookkeeping has three
   independent gaps** — 3 sessions (v2, armor-genericity, benchy foreign
   mesh): a part can be silently never assigned in a wave (masked by a
   sibling that bootstrap-converged on its own, so the launch count looked
   complete); an agent's *interim* best can be consumed as if it were
   finished (one catalog bake ran against a still-polishing best); and a
   `gates.mjs` change mid-run leaves already-`done` parts unrevalidated
   against the new gate. **Action:** added three process rules to
   `.claude/skills/inverse-cad.md` — checklist the wave's launched-vs-unconverged
   set before waiting, treat "best/ exists" and "phase: done" as separate
   facts, and re-evaluate stored bests after any gate change. The
   heavier fix (a real status/convergence-driver script) is a backlog item
   below, not a doc change.
2. **[tooling] A warm dev-server + browser loop for iterating on *interactive*
   UI features is still missing** — 2 sessions this batch (multi-part
   assembly view, 3MF packing strategy), and both note this is a repeat ask
   from earlier retro cycles too. `model:preview`'s render daemon already
   solved this for static model code; nothing equivalent exists for a
   feature that needs clicks/typing across ~5 verification rounds, so each
   round pays a fresh ~4s WASM boot + session build inside a cold
   Playwright run. Filed as a backlog tooling item (extending the existing
   daemon, not a doc fix).
3. **[deform API] `scatter`'s `offset` and `round`'s radius are both
   trial-and-error to size correctly** — surfaced across 3 independent
   rework agents each (catalog-refresh batch): `offset` needs sizing
   against the *instance's* own half-thickness, not the base's scale (two
   agents fully buried their instances on the first pass); `round`'s
   documented thin-shell ceiling is real but agents still wanted a plain
   rule of thumb for the common case. **Action:** added a worked numeric
   example for `offset` and a "radius ≈ 4–6% of edge length" starting
   point to `public/ai/deform.md`. The complementary code-level asks
   (region-scoped `smoothWeld`/`round`, a `placedCount`/dry-run mode for
   `scatter`) are tracked as backlog, not doc fixes.
4. **[testing] Short scrollable lists silently no-op drag targets below the
   default viewport's clip** — 1 session (part-grouping), but concrete and
   cheap to fix: a drag-and-drop e2e against the parts rail passed locally
   at first only because rows were visible, then silently missed once the
   list needed a scroll. **Action:** added a line to
   `docs/playwright-guide.md`'s existing viewport-gotcha list.
5. **[process, no action] The tool-history-repair "single source of truth"
   and "OpenAI 400 with an Anthropic-shaped body" diagnostics gaps**
   (tool-history-auto-repair) are both real but already filed as `#914`;
   no further action needed here beyond noting the diagnostics-field idea
   in the backlog below.
